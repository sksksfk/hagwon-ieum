# 이음 (Ieum)

가족이 아이들의 주간 학원 일정을 정리하는 정적 웹 앱입니다. 바닐라 HTML/CSS/JavaScript로 동작하며 정보는 브라우저 localStorage에 저장됩니다. 서버 계정이나 동기화 기능은 없습니다.

## 주요 기능

- 여러 아이 정보 및 연락처 관리
- 요일별 반복 일정과 특정 날짜 예외 일정
- 이동 수단(도보 포함), 이동 시간 설정, 일정 간 겹침 경고
- 태권도 후보 시간대 자동 제안 및 수동 편집
- 연락처 전화(tel:)·문자(sms:) 링크
- 편집 가능한 하단 안내/광고 자리표시 문구. 추적기 없음
- JSON 백업 가져오기/내보내기(평문), ICS 내보내기
- PWA 설치 및 기본 오프라인 사용

## 개인정보와 안전

정보는 기본적으로 사용하는 브라우저의 로컬 저장소에 있습니다. 브라우저 데이터 삭제 등으로 정보가 사라질 수 있으니 백업을 보관하세요. JSON 백업은 **암호화되지 않은 평문**이며 아이 이름·일정·연락처 등 민감한 내용이 포함될 수 있습니다. 공유 전에 확인하고 안전하게 보관하세요.

앱은 서버, 로그인, 동기화, GPS, 푸시 알림, 자동 긴급 출동/연락 기능을 제공하지 않습니다. 전화·문자 링크는 사용자가 직접 실행합니다. 의료·안전을 보장하거나 전문적인 일정·이동 판단을 대체하지 않습니다. 표시된 경고와 시간은 참고용이므로 사용자가 확인해야 합니다.

## 실행 및 테스트

Node.js 20 이상, 외부 패키지 의존성 없음. `npm test`는 `node --test`를 실행하고 `npm start`는 `http://localhost:4173`에서 서버를 시작합니다.

## GitHub Pages 배포 준비

GitHub Actions workflow는 루트의 `index.html`, `styles.css`, `app.js`, `core.js`, `manifest.webmanifest`, `sw.js`, `icon.svg`, `icon-512.png`만 `_site/`에 복사해 Pages artifact로 올립니다. 테스트와 문서는 배포하지 않습니다. 저장소 준비만으로 실제 업로드나 배포가 이루어지지는 않습니다.

1. GitHub 저장소를 만들고 파일을 커밋·푸시합니다.
2. **Settings → Pages → Build and deployment → Source**에서 **GitHub Actions**를 선택합니다.
3. **Actions**에서 `Deploy to GitHub Pages`가 실행되었는지 확인합니다. 기본 브랜치 푸시 또는 수동 실행으로 배포할 수 있습니다.
4. 성공 후 Pages 설정에서 공개 URL을 확인합니다.

배포할 앱 파일은 저장소 루트에 있어야 합니다. HTTPS 페이지에서도 로컬 저장소는 브라우저·기기마다 분리되므로 백업을 관리하세요. 테스트는 `tests/`에 둡니다. 라이선스는 MIT입니다.

## 빠른 사용

첨부된 `이음-가족시간표.html` 파일은 다운로드하여 PC 브라우저에서 바로 열 수 있습니다. 파일 미리보기에서는 스크립트가 실행되지 않을 수 있습니다. 모바일에서 널리 공유하려면 GitHub Pages의 HTTPS 주소 사용을 권장합니다. 파일 버전의 저장소 동작은 브라우저마다 다르므로 중요한 정보는 백업하세요. 단일 파일은 PWA 설치·오프라인 캐시 등록을 하지 않습니다.

프로젝트 압축을 푼 뒤 터미널에서:

```sh
npm test
npm start
# 단일 HTML을 다시 만들려면
npm run build
```

태권도 자동 배치는 요일·가능 시간대·수련시간·이동시간을 받아 10분 간격으로 검색합니다. 기존 반복 태권도는 유지하고, 다른 반복 일정과 이미 등록된 같은 요일의 일회성 일정도 피합니다. 일회성 일정은 보수적으로 모든 주의 배치 후보에 반영하므로 더 좋은 시간이 있어도 건너뛸 수 있습니다. 미리보기에서 확인한 뒤 적용하며 수동 편집할 수 있습니다. 운영시간·차량 운행은 도장에 확인해야 합니다.

## 저장소 업로드

빈 GitHub 저장소를 만들고 압축을 푼 **내부 파일**을 저장소 루트에 넣으세요. `.github/workflows/deploy.yml`도 반드시 포함합니다. Git을 쓴다면:

```sh
git init
git add .
git commit -m "Build Ieum family schedule app"
git branch -M main
git remote add origin https://github.com/YOUR_NAME/YOUR_REPO.git
git push -u origin main
```

`YOUR_NAME/YOUR_REPO`는 본인의 저장소로 바꿉니다. GitHub Pages 설정은 위 안내를 따르세요. 사용자 백업이나 연락처를 커밋하지 마세요. 배포 workflow는 먼저 계산 테스트를 실행합니다. 이 저장소는 기기 저장형 앱 소스입니다. 온라인 실행은 GitHub Pages 배포 성공 후 이용할 수 있습니다.

## 운영 확장 전 필요한 작업

여러 보호자·학원 간 실시간 공유에는 별도 서버, 인증, 역할별 권한, 동의·보관·삭제 정책과 보안 검토가 필요합니다. 실제 광고 송출에는 광고 심사·표시 정책과 개인정보 동의 설계가 필요합니다. 현재 버전은 이 기기용 기능 앱이며 서버 운영 서비스가 아닙니다.

## 1.1 업데이트: 보기 설정·현재 시각·학원비

- 상단 **보기 설정**: 오늘 자동 선택 또는 이번 주의 지정 요일 우선 표시, 하루/일주일 기본 보기 선택. 화면의 하루/주간 버튼으로 즉시 전환합니다.
- 하루 시간 눈금: 00~24시 눈금과 자녀별 수업/이동 막대, 기기 시계 기준 현재 시각선. 30초마다 갱신하며 오늘을 선택했을 때만 선을 표시합니다. 현재 시간대의 수업은 시간표상 진행 중으로 강조합니다. 실제 참석 여부 확인은 아닙니다.
- 시간표 하단 **학원비 등록**: 자녀·학원명·월 금액·매월 납부일·시작/종료 월·기본 납부 방식(자동납부/직접 카드/계좌 송금/현금)을 기록합니다. 같은 학원에 복수 항목도 등록할 수 있으니 중복 입력에 주의하세요.
- 학원비는 선택한 월의 날짜순으로 나오며, 자녀 필터와 월 이동을 지원합니다. 해당 날짜가 없는 달에는 말일을 사용합니다.
- **납부 확인**에서 실제 납부일·실제 금액·실제 방식을 저장하면 해당 월만 완료됩니다. 다음 달은 다시 예정으로 표시합니다. 자동납부 설정만으로 완료 처리하지 않습니다.
- 완료 기록은 당시 학원명·자녀·금액·방식·예정일을 보관합니다. 이후 반복 회비를 수정해도 완료 기록은 바뀌지 않습니다. 완료 취소는 해당 월 기록만 지웁니다. 전체 항목 삭제는 그 납부기록도 삭제하므로 수강 종료에는 종료 월 지정을 권장합니다.
- 기존 v1 백업은 일정과 연락처를 유지한 채 기본 설정·빈 회비 목록을 추가해 읽습니다. 새 파일을 다른 위치에 저장하면 브라우저의 파일별 저장소가 달라질 수 있으므로 기존 앱에서 JSON 백업 후 새 앱에서 불러오세요.
- 금액과 납부 메모도 민감한 정보입니다. 카드번호·계좌번호·인증정보를 입력하지 말고 백업을 공개하지 마세요. 이 기능은 수동 기록이며 결제·은행조회·자동 알림이 아닙니다.

## 1.2 업데이트: 초등학교·방과후·돌봄

메뉴 **학교 · 방과후 · 돌봄**에서 자녀·요일을 선택하여 설정합니다. 주말도 상단 날짜를 고른 뒤 설정할 수 있습니다.

1. 정규수업 시작과 마치는 시간을 요일별로 입력합니다. 등교 이동수단·이동시간도 설정합니다.
2. 방과후 과목을 여러 개 추가합니다. 과목명·시작/종료는 필수, 교실·담당자·업무 연락처는 선택입니다. 정규수업 이후여야 하며 방과후 과목끼리 겹칠 수 없습니다.
3. 돌봄을 이용하는 요일에는 이용 시작·퇴실 시간과 **선생님 이름, 교실명, 교실 전화번호**가 필수입니다. 선생님 업무 전화는 선택이며 개인 휴대전화번호를 필수로 요구하지 않습니다. 학교 공식 전화번호를 쓰고 내선은 메모에 적습니다. 번호의 실제 연결 여부는 학교에 확인해야 합니다.
4. 학교에서 나오는 방법·차량명·탑승/인계 장소·연결 연락처를 기록합니다. 다음 학원까지의 이동시간은 학원 일정에 설정합니다.

학교 출발 가능시간은 정규수업·방과후·돌봄 중 가장 늦은 종료 시각입니다. 돌봄 이용시간 중간의 방과후는 자동으로 분리하여 돌봄 → 방과후 → 돌봄으로 표시합니다. 어느 활동에도 배정되지 않은 교내 대기시간은 보호 확인 경고로 표시합니다. 앱이 보호나 인계를 보장하지 않습니다.

기존 수동 학교 일정은 삭제하지 않습니다. 학교생활 계획이 있는 날짜·요일에만 기존 학교 종류 일정 대신 생성된 계획을 보여줍니다. 계획을 지우면 기존 학교 일정이 다시 나타날 수 있습니다. 학원 일정은 자동으로 이동하거나 삭제하지 않고, 학교 출발 가능시간보다 이동 출발이 빠르면 경고합니다. 태권도 신규 자동 배치도 학교 체류·이동시간을 고려하지만 기존 태권도 일정은 유지하므로 경고를 확인하세요.

**이 날짜만 변경 / 휴업일**로 해당 날짜의 돌봄 퇴실·방과후 등을 바꿀 수 있습니다. 등교함을 해제하면 그 날짜는 학교 일정을 표시하지 않습니다. 학원은 별도로 확인합니다. 날짜 예외는 반복 요일보다 우선합니다. 날짜 예외를 삭제하면 반복 계획으로 돌아갑니다. 반복 요일 설정 변경은 과거 주에도 반영되므로 학기별 이력 보관 용도는 아닙니다.

돌봄 교실 연락처는 당일 학교 요약, 비상 연락망과 비상 연락창에서 확인합니다. 비상 연락창은 실제 오늘의 계획을 우선하며 반복 요일의 다른 연락처도 요일과 함께 표시하므로 담당일을 확인하세요. 전화 링크는 기기의 전화 앱을 열 뿐 자동 통화·문자·퇴실 확인을 하지 않습니다. 예시 번호 02-0000-0000 등은 전화 링크를 막아 두었으며 실제 연락처로 바꿔야 합니다.

학교생활·선생님/교실 연락처도 평문 JSON 백업에 포함됩니다. GitHub에 사용자 백업을 올리지 마세요. 기존 1.0/1.1 데이터에는 빈 학교생활 목록을 보완하여 읽습니다. 업데이트 전 기존 파일에서 JSON 백업을 보관하세요.
