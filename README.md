## 도장별 실제 수업부에 맞춘 자동 배치

태권도 자동 배치에서 도장을 저장·선택하고 요일마다 다른 시작 시각을 쉼표로 입력합니다. 빈 요일은 수업 없음으로 처리합니다. 수업시간과 차량 운행시간도 도장마다 바꿀 수 있습니다. 고정 수업부에서는 등록된 시작 시각에만 배치하며 맞는 부가 없으면 건너뜁니다. 기존 자유 시간범위 10분 탐색도 별도로 선택할 수 있습니다.

글로벌태권얍 예시: 13:00, 14:30, 16:00, 17:30, 19:00 시작 / 수업 60분 / 수업 후 차량 운행 30분. 마지막 부는 19:00–20:00 수업, 20:00–20:30 운행 계획입니다. 사용자에게 제공받은 시각을 예시로 넣었으며 운영 요일은 확정하지 않았습니다. 예시 버튼은 현재 선택한 수련 요일에만 채우므로 실제 요일·노선·탑승·인계 시각을 도장에 확인하세요.

수업 전 도장까지의 이동은 별도 입력합니다. 수업 후 도장 차량을 이용하는 아이는 운행시간만큼 다음 일정과 겹치지 않게 비워 두고, 차량 미이용 체크 시 수업 종료만 기준으로 합니다. 차량 운행 구간은 실제 하차 시각 보장이 아닌 계획값입니다. 기존 다른 일정의 수업 후 이동도 함께 충돌 검사하며, 하루 이동 합계·시간 눈금·목록과 ICS 별도 이동 이벤트에 반영합니다. 개별 일정의 수업 후 이동은 편집창의 추가 차량 시간에서 수정할 수 있습니다.

도장 설정만 저장하거나 일정 적용과 함께 저장할 수 있습니다. 여러 도장을 보관할 수 있고, 도장 설정 변경·삭제가 기존 일정을 자동 재배치하지 않습니다. 기존 반복 태권도는 보존하므로 필요하면 직접 편집하세요. 도장 설정은 가족 보관함/백업 안에 암호화되며 예전 자료에는 빈 도장 목록을 보완합니다.

2026.12.31까지 가입 없는 가상 예시에서 자동 배치 설정과 미리보기도 볼 수 있습니다. 체험에서는 도장 설정·제안 일정을 실제로 저장하지 않습니다.

## 간편 진입과 체험 안내
2026년 12월 31일(한국시간)까지 가입·전체 전화번호 등록·암호 입력 없이 가상 예시를 둘러볼 수 있습니다. 체험 화면은 읽기 전용이며 저장한 가족 자료를 열지 않습니다. 의견: 010-9977-5002 / sportsn@naver.com. 아이 실명·세부 동선·전화번호를 공개 의견에 포함하지 마세요.

**간편 PIN은 강한 암호와 같은 보호 수준이 아닙니다.** IndexedDB에 추출 불가능한 기기 키와 2중 암호화된 복구 암호를 보관합니다. PIN 5회 실패 시 간편 기록만 제거하며 가족 자료는 남아 복구 코드로 열 수 있습니다. 기기/브라우저 프로필 탈취, 같은 출처의 악성 코드나 확장 프로그램에는 강한 방어가 아닙니다. 공용 기기에서는 켜지 마세요. Web Crypto의 추출 불가능 표시는 하드웨어 보안 저장을 뜻하지 않습니다. 지문·얼굴 인증은 이번 버전에 구현하지 않았습니다.

복구 코드/기존 복구 암호는 기기 변경, 백업 복원, PIN을 잃거나 5회 실패한 때에 필요합니다. 이 코드는 운영자가 복구하지 못합니다. 간편 PIN 사용 시에는 아래 1.3 문서의 “암호를 기기에 보관하지 않음”보다 이 절의 선택적 암호화 보관 안내가 우선합니다.

# 이음 (Ieum) · v1.3

[앱 실행](https://sksksfk.github.io/hagwon-ieum/) · [보안 안내](SECURITY.md)

**처음 사용할 때 12자 이상의 길고 고유한 보관함 암호를 직접 만드세요. 암호를 잊으면 복구할 수 없습니다.** 이전 앱 탭을 닫은 뒤 업데이트하세요. 새 버전에서 암호화 이전을 마치기 전까지 기존 1.2 자료는 평문 상태입니다.


가족이 아이들의 주간 학원 일정을 정리하는 정적 웹 앱입니다. 바닐라 HTML/CSS/JavaScript로 동작하며, 1.3부터 가족 자료는 사용자 암호로 암호화한 뒤 브라우저 localStorage에 저장합니다. 서버 계정이나 동기화 기능은 없습니다.

## 주요 기능

- 여러 아이 정보 및 연락처 관리
- 요일별 반복 일정과 특정 날짜 예외 일정
- 이동 수단(도보 포함), 이동 시간 설정, 일정 간 겹침 경고
- 태권도 후보 시간대 자동 제안 및 수동 편집
- 연락처 전화(tel:)·문자(sms:) 링크
- 편집 가능한 하단 안내/광고 자리표시 문구. 추적기 없음
- 암호화 JSON 백업 가져오기/내보내기 및 이전 평문 백업 가져오기, ICS 내보내기
- PWA 설치 및 기본 오프라인 사용

## 개인정보와 안전

정보는 기본적으로 사용하는 브라우저의 로컬 저장소에 있습니다. 브라우저 데이터 삭제 등으로 정보가 사라질 수 있으니 백업을 보관하세요. 현재 기본 백업은 **암호화된 파일**입니다. 단, 1.2 이하의 예전 JSON, ICS 캘린더와 인쇄물은 평문이므로 민감한 정보가 노출될 수 있습니다. 공유 전에 확인하고 안전하게 보관하세요.

앱은 서버, 로그인, 동기화, GPS, 푸시 알림, 자동 긴급 출동/연락 기능을 제공하지 않습니다. 전화·문자 링크는 사용자가 직접 실행합니다. 의료·안전을 보장하거나 전문적인 일정·이동 판단을 대체하지 않습니다. 표시된 경고와 시간은 참고용이므로 사용자가 확인해야 합니다.

## 실행 및 테스트

Node.js 20 이상, 외부 패키지 의존성 없음. `npm test`는 `node --test`를 실행하고 `npm start`는 `http://localhost:4173`에서 서버를 시작합니다.

## GitHub Pages 배포 준비

GitHub Actions workflow는 루트의 `index.html`, `styles.css`, `app.js`, `core.js`, `vault.js`, `manifest.webmanifest`, `sw.js`, `icon.svg`, `icon-512.png`만 `_site/`에 복사해 Pages artifact로 올립니다. 테스트와 문서는 배포하지 않습니다. 저장소 준비만으로 실제 업로드나 배포가 이루어지지는 않습니다.

1. GitHub 저장소를 만들고 파일을 커밋·푸시합니다.
2. **Settings → Pages → Build and deployment → Source**에서 **GitHub Actions**를 선택합니다.
3. **Actions**에서 `Deploy to GitHub Pages`가 실행되었는지 확인합니다. 기본 브랜치 푸시 또는 수동 실행으로 배포할 수 있습니다.
4. 성공 후 Pages 설정에서 공개 URL을 확인합니다.

배포할 앱 파일은 저장소 루트에 있어야 합니다. HTTPS 페이지에서도 로컬 저장소는 브라우저·기기마다 분리되므로 백업을 관리하세요. 테스트는 `tests/`에 둡니다. 최신 버전은 LICENSE의 개인·비상업용 조건을 따릅니다. 이전 MIT 공개분은 별개입니다.

## 빠른 사용

첨부된 `이음-가족시간표.html` 파일은 다운로드하여 PC 브라우저에서 바로 열 수 있습니다. 파일 미리보기에서는 스크립트가 실행되지 않을 수 있습니다. 모바일에서 널리 공유하려면 GitHub Pages의 HTTPS 주소 사용을 권장합니다. 파일 버전의 저장소 동작은 브라우저마다 다르므로 중요한 정보는 백업하세요. 단일 파일은 PWA 설치·오프라인 캐시 등록을 하지 않습니다.

프로젝트 압축을 푼 뒤 터미널에서:

```sh
npm test
npm start
# 단일 HTML을 다시 만들려면
npm run build
```

태권도 자동 배치는 요일·가능 시간대·수련시간·이동시간을 받아 10분 간격으로 검색합니다. 기존 반복 태권도는 유지하고, 다른 반복 일정과 이미 등록된 같은 요일의 일회성 일정도 피합니다. 일회성 일정은 보수적으로 모든 주의 배치 후보에 반영하므로 더 좋은 시간이 있어도 건너뛸 수 있습니다. 미리보기에서 확인한 뒤 적용하며 수동 편집할 수 있습니다. 운영시간·차량 운행은 도장에 확인해야 합니다.

## 저장소 업로드

빈 GitHub 저장소를 만들고 압축을 푼 **내부 파일**을 저장소 루트에 넣으세요. `.github/workflows/deploy.yml`도 반드시 포함합니다. Git을 쓴다면:

```sh
git init
git add .
git commit -m "Build Ieum family schedule app"
git branch -M main
git remote add origin https://github.com/YOUR_NAME/YOUR_REPO.git
git push -u origin main
```

`YOUR_NAME/YOUR_REPO`는 본인의 저장소로 바꿉니다. GitHub Pages 설정은 위 안내를 따르세요. 사용자 백업이나 연락처를 커밋하지 마세요. 배포 workflow는 먼저 계산 테스트를 실행합니다. 이 저장소는 기기 저장형 앱 소스입니다. 온라인 실행은 GitHub Pages 배포 성공 후 이용할 수 있습니다.

## 운영 확장 전 필요한 작업

여러 보호자·학원 간 실시간 공유에는 별도 서버, 인증, 역할별 권한, 동의·보관·삭제 정책과 보안 검토가 필요합니다. 실제 광고 송출에는 광고 심사·표시 정책과 개인정보 동의 설계가 필요합니다. 현재 버전은 이 기기용 기능 앱이며 서버 운영 서비스가 아닙니다.

## 1.1 업데이트: 보기 설정·현재 시각·학원비

- 상단 **보기 설정**: 오늘 자동 선택 또는 이번 주의 지정 요일 우선 표시, 하루/일주일 기본 보기 선택. 화면의 하루/주간 버튼으로 즉시 전환합니다.
- 하루 시간 눈금: 00~24시 눈금과 자녀별 수업/이동 막대, 기기 시계 기준 현재 시각선. 30초마다 갱신하며 오늘을 선택했을 때만 선을 표시합니다. 현재 시간대의 수업은 시간표상 진행 중으로 강조합니다. 실제 참석 여부 확인은 아닙니다.
- 시간표 하단 **학원비 등록**: 자녀·학원명·월 금액·매월 납부일·시작/종료 월·기본 납부 방식(자동납부/직접 카드/계좌 송금/현금)을 기록합니다. 같은 학원에 복수 항목도 등록할 수 있으니 중복 입력에 주의하세요.
- 학원비는 선택한 월의 날짜순으로 나오며, 자녀 필터와 월 이동을 지원합니다. 해당 날짜가 없는 달에는 말일을 사용합니다.
- **납부 확인**에서 실제 납부일·실제 금액·실제 방식을 저장하면 해당 월만 완료됩니다. 다음 달은 다시 예정으로 표시합니다. 자동납부 설정만으로 완료 처리하지 않습니다.
- 완료 기록은 당시 학원명·자녀·금액·방식·예정일을 보관합니다. 이후 반복 회비를 수정해도 완료 기록은 바뀌지 않습니다. 완료 취소는 해당 월 기록만 지웁니다. 전체 항목 삭제는 그 납부기록도 삭제하므로 수강 종료에는 종료 월 지정을 권장합니다.
- 기존 v1 백업은 일정과 연락처를 유지한 채 기본 설정·빈 회비 목록을 추가해 읽습니다. 새 파일을 다른 위치에 저장하면 브라우저의 파일별 저장소가 달라질 수 있으므로 기존 앱에서 JSON 백업 후 새 앱에서 불러오세요.
- 금액과 납부 메모도 민감한 정보입니다. 카드번호·계좌번호·인증정보를 입력하지 말고 백업을 공개하지 마세요. 이 기능은 수동 기록이며 결제·은행조회·자동 알림이 아닙니다.

## 1.2 업데이트: 초등학교·방과후·돌봄

메뉴 **학교 · 방과후 · 돌봄**에서 자녀·요일을 선택하여 설정합니다. 주말도 상단 날짜를 고른 뒤 설정할 수 있습니다.

1. 정규수업 시작과 마치는 시간을 요일별로 입력합니다. 등교 이동수단·이동시간도 설정합니다.
2. 방과후 과목을 여러 개 추가합니다. 과목명·시작/종료는 필수, 교실·담당자·업무 연락처는 선택입니다. 정규수업 이후여야 하며 방과후 과목끼리 겹칠 수 없습니다.
3. 돌봄을 이용하는 요일에는 이용 시작·퇴실 시간과 **선생님 이름, 교실명, 교실 전화번호**가 필수입니다. 선생님 업무 전화는 선택이며 개인 휴대전화번호를 필수로 요구하지 않습니다. 학교 공식 전화번호를 쓰고 내선은 메모에 적습니다. 번호의 실제 연결 여부는 학교에 확인해야 합니다.
4. 학교에서 나오는 방법·차량명·탑승/인계 장소·연결 연락처를 기록합니다. 다음 학원까지의 이동시간은 학원 일정에 설정합니다.

학교 출발 가능시간은 정규수업·방과후·돌봄 중 가장 늦은 종료 시각입니다. 돌봄 이용시간 중간의 방과후는 자동으로 분리하여 돌봄 → 방과후 → 돌봄으로 표시합니다. 어느 활동에도 배정되지 않은 교내 대기시간은 보호 확인 경고로 표시합니다. 앱이 보호나 인계를 보장하지 않습니다.

기존 수동 학교 일정은 삭제하지 않습니다. 학교생활 계획이 있는 날짜·요일에만 기존 학교 종류 일정 대신 생성된 계획을 보여줍니다. 계획을 지우면 기존 학교 일정이 다시 나타날 수 있습니다. 학원 일정은 자동으로 이동하거나 삭제하지 않고, 학교 출발 가능시간보다 이동 출발이 빠르면 경고합니다. 태권도 신규 자동 배치도 학교 체류·이동시간을 고려하지만 기존 태권도 일정은 유지하므로 경고를 확인하세요.

**이 날짜만 변경 / 휴업일**로 해당 날짜의 돌봄 퇴실·방과후 등을 바꿀 수 있습니다. 등교함을 해제하면 그 날짜는 학교 일정을 표시하지 않습니다. 학원은 별도로 확인합니다. 날짜 예외는 반복 요일보다 우선합니다. 날짜 예외를 삭제하면 반복 계획으로 돌아갑니다. 반복 요일 설정 변경은 과거 주에도 반영되므로 학기별 이력 보관 용도는 아닙니다.

돌봄 교실 연락처는 당일 학교 요약, 비상 연락망과 비상 연락창에서 확인합니다. 비상 연락창은 실제 오늘의 계획을 우선하며 반복 요일의 다른 연락처도 요일과 함께 표시하므로 담당일을 확인하세요. 전화 링크는 기기의 전화 앱을 열 뿐 자동 통화·문자·퇴실 확인을 하지 않습니다. 예시 번호 02-0000-0000 등은 전화 링크를 막아 두었으며 실제 연락처로 바꿔야 합니다.

학교생활·선생님/교실 연락처도 백업에 포함됩니다. 1.3 기본 백업은 암호화되지만 이전 버전 JSON은 평문입니다. GitHub에 사용자 백업을 올리지 마세요. 기존 1.0/1.1 데이터에는 빈 학교생활 목록을 보완하여 읽습니다. 업데이트 전 기존 파일에서 JSON 백업을 보관하세요.

## 1.3: 요일별 학원 편집 · 다자녀 · 개인정보 보호

### 학원 · 요일별 편집

새 메뉴에서 자녀와 요일을 고르고 각 학원의 시작/종료, 이동수단, 차량, 장소, 연락처를 편집합니다. 반복 일정은 기본 **이 요일만 변경**으로 열립니다. 예를 들어 월·수·금 영어에서 수요일만 14:30으로 바꾸면 월·금은 원래대로 유지됩니다. 전체 반복 요일 변경, 특정 날짜만 변경도 선택할 수 있습니다. 삭제 역시 해당 요일만 선택할 수 있습니다. 기존 일정의 자녀는 바꾸지 못하게 하여 형제 간 오수정을 줄였습니다. 다른 자녀에게는 새 일정을 추가하세요. 모든 자녀 보기/개별 보기, 자녀별 일정 추가를 제공합니다. 학원 이동 충돌과 학교 출발시간 경고도 유지합니다.

### 보관함 시작과 자료 이전

- 새 설치: 보안 암호를 직접 만들고 빈 보관함에서 시작합니다. 예시 미리보기는 메모리에서만 동작하며 수정·내보내기를 하지 않습니다.
- 기존 자료: 암호를 만든 뒤 기존 v1 자료를 암호화 저장하고, 저장 확인 후 이전 평문 localStorage 항목을 삭제합니다. 이전 앱 탭이 다시 평문을 쓰면 잠급니다. 이미 남아 있는 평문 자료는 다음 잠금 해제에서 사용자 동의 후 정리해야 합니다. 자료가 손상되면 이전 앱/백업에서 복구한 뒤 다시 시도하세요.
- 같은 브라우저·같은 경로의 보관함만 이어집니다. 기기·브라우저·파일 위치가 다르면 암호화 백업으로 옮기세요.
- 암호와 비밀 키를 URL·localStorage·sessionStorage에 보관하지 않습니다. 키는 잠금 해제한 동안 메모리에만 유지합니다.

### 보호 기능과 한계

AES-GCM-256 + PBKDF2-SHA256 310,000회, 새 보관함마다 무작위 salt와 매 저장마다 새 IV를 씁니다. 창 이탈 즉시/2분 미사용/지금 잠금/다른 탭 변경 시 잠금 처리하며, 화면과 편집창에서 이름·장소·연락처 등을 제거하고 키 참조를 해제합니다. 브라우저/운영체제 메모리의 완전 삭제를 보장하는 것은 아닙니다. 비상 연락창도 잠금 중에는 저장한 개인 연락처를 보여주지 않고 112·119만 제공합니다.

잠금 해제 시 화면 가림이 기본입니다. 이름을 첫째·둘째로, 장소·차량·연락처·메모·금액을 비공개로 표시합니다. **일정 시각·요일은 남으며, 편집창·비상 연락창은 사용자가 선택하면 실제 내용을 보여줍니다.** 가림은 권한 분리가 아니므로 주변 사람이 보는 상황에서는 지금 잠금을 쓰세요.

기본 백업은 암호화 `.ieum.json`입니다. 백업과 암호는 따로 보관하고 보관함 암호 변경 후에는 새 백업을 만드세요. 예전 백업 암호는 자동 변경되지 않습니다. 앱의 ICS/인쇄 버튼은 암호 재확인을 요구하지만, 브라우저 메뉴·화면 촬영·이미 만든 파일까지 통제하지는 못합니다. 이전 평문 백업·ICS·인쇄물·메신저 공유본·오래된 앱 탭은 사용자가 정리해야 합니다.

악성코드·악성 확장 프로그램·기기 탈취 상태·관찰된 암호·악성 사이트 업데이트·같은 출처의 악성 코드에는 완전 방어가 아닙니다. GitHub Pages의 같은 계정 하위 앱은 같은 출처를 공유하므로 다른 저장소도 신뢰할 수 있어야 합니다. 엄격한 격리가 필요하면 전용 도메인·독립 출처와 전문 보안 점검을 권장합니다. 휴대전화 화면 잠금·운영체제 업데이트·GitHub 계정 보호도 필요합니다. 범죄 예방을 보장하는 제품으로 사용하지 마세요.
